# A-A-A-A Match 3 RPG — заметки для Claude

Мобильная match-3 RPG в браузере и как PWA. Репозиторий: crashic/A-A-A-A-RPG-Match-3, игра: https://crashic.github.io/A-A-A-A-RPG-Match-3/
С версии 0.1.0 игра делается с нуля (старый код «Осколков Бездны» удалён, он есть в истории git до коммита b3f1c1e).

## Правила работы с пользователем
- Отвечать по-русски, о себе в женском роде («сделала»).
- «ИЗ АРТЕФАКТА» в сообщении пользователя — взять этот элемент из дизайн-системы (ссылка ниже, копия в `design/`).
- Сеттинг: постапокалипсис в фэнтезийной России (Fallout по-русски с киберпанком); герой живёт в бункере и выходит на поверхность за провизией. Валюта — изолента: синяя / чёрная / белая (как золото / серебро / медь, 1:100:100).
- Выбор вариантов и пунктов меню — опросом (AskUserQuestion).
- Устройство: телефон 1080×2460, Android 13+, управление касанием и перетаскиванием. Всё приложение в ГОРИЗОНТАЛЬНОЙ ориентации: CSS ~820×360 (manifest `landscape`, в браузере — `lockLandscape` после входа в полный экран). Если телефон держат вертикально (или выключен автоповорот), всё приложение рисуется повёрнутым на 90° (CSS в конце `style.css`, размеры экрана — `--app-w`/`--app-h`, а не vw/vh); координаты касаний переводить через `toAppPoint`/`appRect`. Проверять и 360×820 (повёрнутый режим).
- Списки (локации, разделы, классы, враги…) — кнопки по высоте содержимого, НЕ растягивать на всю высоту блока.
- Мелкая правка — «в файле X найди это, замени на это»; заметная — файлы целиком с путями; новая подсистема или много файлов — сначала спросить (архив или пуш).
- Перед крупной пересборкой проекта уточнять и объяснять, почему так рациональнее.
- В конце архива указывать версию.
- Перед выпуском СПРАШИВАТЬ пользователя опросом: какой номер версии присвоить и какой текст внести в список изменений (предложить варианты). Самой версию не выбирать и текст не вписывать.
- После правок: проверить Playwright (viewport 820×360 телефон лёжа + ПК 1366×768, без ошибок в консоли; всё должно помещаться по высоте 360 без прокрутки), выставить согласованную `APP_VERSION`, добавить согласованную запись в `js/changelog.js`, закоммитить и запушить в main.
- Список изменений (`js/changelog.js`, открывается нажатием на версию): новая версия сверху, максимально коротко, только главное — «добавили 25 предметов», «создали систему квестов».
- Формат версии у пользователя свободный (например `0.1.a`); для обновления важна только смена строки, порядок номеров не важен.

## Дизайн
- Весь интерфейс и графика — по дизайн-системе пользователя: https://claude.ai/artifact/R918BS9sRLVB4Q6fLH64d4. Пользователь её часто дорабатывает — ПЕРЕД ЛЮБОЙ правкой интерфейса (не только графики) открывать макет, сверять с копией в `design/` и обновлять её, без напоминаний (`README.md` — правила, `tokens.json` — палитра, `icon-guide.md` — как рисовать иконки, `components/*/` — образцы).
- Палитра фэнтези-кита: фон экранов — закатное небо `bg-sky-top → bg-sky-mid → bg-sky-bottom`; камень `bg-canvas` — панели; ячейки поля `bg-cell` / `bg-cell-alt` шахматкой; 7 камней по ступеням светлоты (у каждого `-light` и `-dark`): `gem-amethyst` (треугольник), `gem-sapphire` (капля), `gem-ruby` (квадрат), `gem-emerald` (шестиугольник), `gem-aquamarine` (крест), `gem-topaz` (звезда), `gem-pearl` (круг). Интерфейс: `ui-outline` (обводка), `ui-metal` (рамки), `ui-primary` («да», текст на ней тёмный `ui-outline`), `ui-danger` («нет», светлый текст), `ui-reward` (золото, тёмный текст), `ui-ribbon` (ленты, магазин), `ui-parchment`, `ui-gold-shadow`; текст `text-primary/secondary/muted`.
- Фишки (`GemsElemental`, вариант A): одинаковый сквиркл цвета камня, внутри иконка ресурса тёмным тоном (55 %), поверх «Верхний глянец» (`#gemGlossGrad`; ободок `gemRim` виден только у выбранной фишки); ресурсы: рубин — топливо, аквамарин — детали, изумруд — травы, топаз — радиация, сапфир — металл, аметист — плёнка, жемчуг — документы. Выбор — без увеличения, ободок яркий; подсказка — мигает на 20 % ярче + «Полосы». Поле (`BoardSample`) 9×9, клетка 46 px, фишка 40 px. Те же плитки-иконки для фракций, рас, классов и пола — `iconTile` (силуэты в `js/originIcons.js`).
- Базовые элементы плоские; «стёкла» (`GlassOverlays`) накладываются отдельно, не больше двух на элемент.
- Цвета только через переменные `css/tokens.css`; он генерируется: `python3 tools/build-tokens.py` (после обновления `design/tokens.json`).
- Кнопки `.btn` + цвет: `green` — главное действие (`ui-primary`), `red` — выход/опасность, `orange` — награда, `purple` — магазин, `stone` — второстепенное; `round` — круглая иконка. Заголовок экрана — `.ribbon` (`ui-ribbon` с хвостами) по центру экрана в `.screenHead`, контейнер — `.panel` (камень `bg-canvas` с кромкой `ui-metal`). Поле — клетки шахматкой на подложке `ui-outline` (без рамки вокруг — так просил пользователь).
- Шрифты — три роли из макета (`TypeSystem`): Noto Sans Display — заголовки; Noto Sans — кнопки, меню, основной текст; IBM Plex Sans — мелкий текст и цифры (tabular-nums). В CSS — готовые стили `font: var(--type-title|heading|score|button|menu|body|body-strong|small|stat|caption)` и трекинг `var(--type-<стиль>-ls)` из `css/tokens.css`. Файлы локально в `fonts/` (не Google Fonts — нужен офлайн), подключены в `css/fonts.css`.

## Структура
- Движок: HTML + CSS + JS, классические скрипты с общей глобальной областью.
- Каждая функция — отдельный файл в `js/`, имя файла = имя функции. Порядок подключения в `index.html` важен, `js/main.js` последний.
- Спрайты — в `sprites/`.
- Новый скрипт или стиль подключать в `index.html`, затем `python3 tools/update-sw.py` — он пересобирает список `FILES` в `sw.js` (скрипты, стили, шрифты, спрайты).
- Экраны — `<section class="screen">` в `index.html` (menu, characters, create, intro, settings, game, map, bye), переключение `showScreen(id)`; каждый переход пишется в history, «Назад» телефона возвращает на предыдущий экран через `renderScreen(id)`.
- Персонаж (таблицы автора): иерархия Фракция → Раса → Класс: фракции `js/factions.js` (Совет Управляющих и Союз Вольных — по три расы; Пресса — фракция и раса сразу, 7 классов: 4 адаптированных + 3 уникальных; у класса Прессы `side` — фракция класса (Совет: Инженер, Надзиратель, Архивариус; Союз: Механик, Засадник, Бард; Хронист — нейтральный); на экранах классы Прессы — две колонки по фракциям, Хронист посередине — `fillPressColumns`), расы `js/races.js` (у расы `classes` — доступные классы с бонусом), классы `js/classes.js`, пол `js/genders.js`. Бонус «+1 % к ресурсу» усиливает фишку в бою — `gemBonus`. Создание: экран «Происхождение» (`renderOriginStep`: фракции, расы, Пресса посередине; недоступное — чёрно-белое) → «Класс» (`renderClassStep`: классы фракции `factionClassList`, имя, пол, «Создать персонажа»; недоступный расе класс — «Таких выживших не существует»), «Случайно» — `randomCharacter`. На сенсорных экранах имя вводится своей клавиатурой (`#keyboard`, `renderKeyboard`) — системная не поворачивается вместе с игрой. В ячейке хранится `{ name, classId, genderId, raceId, factionId, level, xp, tape, lastEnemy, created, updated, version }`.
- Навыки (документ автора, адаптированы к бою): `js/skills.js` — по 2 навыка на «раса:класс» (адаптированные классы Прессы берут навыки расы-источника — `PRESS_SKILL_SOURCE`), у навыка `lore` (оттенок расы) и `text` (что делает в бою). Пассивные (`effects` с `on`: gather, gemPct, stack, allPct, start, firstHit, dmgReduce, lowHp, shieldBroken, single, afterActive, notes) — `hasPassive`, `skillGemPct`, `skillAfterGather`, `skillReduceHit`, `skillAfterHeroHit`, `skillTurnEnd`, `skillBattleStart`. Активные — кнопки за ману под панелью героя (`renderSkillBar`, `canUseSkill`, `useSkill`; act: show, ward, shield, heal, buff, undo — ход не тратят; calibrate, convert — меняют поле и тратят ход). Состояние — `battle.skill` (`createSkillState`, сохраняется с боем). Навыки показываются на экране выбора класса. Боевые навыки классов — `js/classSkills.js` (`CLASS_SKILLS`, по одному на класс, у всех рас одинаковый, первым в `heroSkills`): активный за одну ману, ход не тратит, перезарядка `cooldown` ходов игрока (`battle.skill.cooldowns`, уменьшается в `skillTurnEnd`), act `strike` — `skillStrike` (mult × атака, pierce, breakShield, drain, ward, selfShieldPct, lifesteal); на кнопке — значок маны, цена и перезарядка.
- Стиль игровых текстов (навыки, враги, лор): юмор с сарказмом, постапокалиптический СССР, ориентиры — WoW, Fallout, Аллоды Онлайн.
- Характеристики (как в WoW Classic): `js/statsConfig.js` (`STATS` — Сила/Ловкость/Выносливость/Интеллект/Дух, коэффициенты), база классов `js/classStats.js`, названия по расам `js/statNames.js` (стили council/union/under/press — тексты автора, `statName`, подсказка `statTipText`). Значение = база класса + `hero.points` (розданные очки); свободных — `statPointsFree`. В бою — `createHeroFighter` (атака, здоровье, крит `rollCrit`, запас/приток маны `manaMax`/`manaPct`, щит за Детали и лечение навыков `healPct`). Свободных очков — 5 за уровень начиная со 2-го (`statPointsTotal`). Экран «Персонаж» (`character`, `renderCharacter`): слева шапка `renderCharHead` (имя по центру, уровень и опыт), кукла `renderDoll` (пары слотов слева–справа по порядку автора: Голова–Плечи, Амулет–Грудь, Пояс–Руки, Кольцо–Ноги, Кольцо–Обувь, Оружие–Оружие — `DOLL_SLOTS` в `js/inventoryConfig.js`; в слотах значки `slotIcon`, название — подсказкой; оружие вдвое выше; под куклой 5 рун), характеристики `renderStatBlock` («−/+» `changeStat`, сброс `resetStats` — оранжевый, если есть розданные очки, с подтверждением; только вне боя, в бою кнопок нет), вкладки класса, фракции и расы `renderCharTabs` (`charTab`); справа инвентарь `renderInventory` (6 тёмных слотов сумок + «+», ячейки). Пустые слоты — `emptySlot`. Значки характеристик — `statChip`/`renderStatChips` (меню, создание персонажа). Раздел «Характеристики» в глоссарии.
- Подсказки — ТОЛЬКО общим стилем, никаких `title`: `attachTip`/`showTip`/`hideTip` (`#tip`) или атрибуты `data-tip`/`data-tip-title` (`setupTips`): ПК — наведение, телефон — касание; фон камень, заголовок «Небо низ», текст вторичный, рамка «Обводка». Пассивные навыки в бою — иконки с подсказкой.
- Полосы прокрутки — тонкие 4 px: фон «Ячейка», ползунок «Обводка», стрелки «Небо низ» (CSS в конце `style.css`).
- После боя экран боя убирается: в истории его заменяет карта, поверх — окно итогов («Закрыть», «Ещё раз» → `enterGame(true)`). На карте справа вертикальное меню иконок (Персонаж, Глоссарий, Фишки, В главное меню — `goHome`).
- Меню боя — одна кнопка справа внизу (`#btnBattleMenu`, `toggleBattleMenu`), список с иконками `#battleMenu`: Фишки, Персонаж, Глоссарий, Карта врагов, В главное меню.
- «Начать игру» без персонажа в выбранной ячейке открывает создание, с персонажем — «Продолжить» → игра (`enterGame`).
- После «Создать» — шуточная заставка (экран `intro`: своя история автора для каждой пары «раса:класс» в `js/introText.js` (`INTRO_STORIES`), выбор — `introStory`, адаптированные классы Прессы берут историю расы-источника; `playIntro`/`finishIntro`/`stopIntro`), затем игра.
- Экран боя: слева панель игрока (`#heroPanel`), по центру поле на всю высоту без отступов (`BOARD_PAD = 0`, размер — `computeBoardLayout`), справа панель врага (`#enemyPanel`), справа внизу — одна кнопка меню боя; слева под панелью героя — кнопки навыков и иконки пассивных (не переполнять высоту 360). Щит, опыт и мана — полосы одной высоты (14 px), значки у полос одного размера, изолента — по правому краю. Панели строит `buildFighterPanel`, обновляет `renderBattle` → `renderFighterPanel` (полосы `setBar`, всплывающие цифры `showFloat`).
- Враги: характеристики по уровню (`enemyStats` → `applyStats`, общий с героем; `createEnemyFighter`), активный навык за ману у каждого врага — `js/enemySkills.js` (`ENEMY_SKILLS` по id врага; `enemyUseSkill` в начале хода врага, ход не тратит, перезарядка `battle.skill.enemyCd`; эффекты как у `skillStrike(skill, 'enemy')`, `weaken` — ослабляет удары героя, `heroWeakened`); навык автора из `zones.js` — пассивная иконка с подсказкой. Под панелью врага — значки характеристик и навыки (`renderEnemySkill`).
- Бой как в Puzzle Quest (`js/battleConfig.js`): ход по очереди, фишки срабатывают для ходящего (роли — из дизайн-системы): топливо урон, детали щит (копится в бою, поглощает урон первым), металл, травы и плёнка — три маны (синяя, зелёная, фиолетовая; на навыки), документы опыт, радиация изолента; фишки НЕ лечат (лечат только навыки), полоса здоровья красная с сердцем (`heartIcon`); ещё ход — ряд 4+ или 5+ одинаковых вместе крестом/«Г»/«Т» (`earnsExtraTurn`, `largestGroup`, `EXTRA_TURN_GROUP`); бот (`scoreMove`): никогда не пропускает ряд 4+/группу 5+, потом урон, щит, мешает игроку собрать ману его навыков (`heroNeedGems`, `bestGatherOf`), бесполезное себе не ценит; в ход игрока у поля золотая рамка (`.board.heroTurn`), клетка под выбранной фишкой — золотая обводка (`.cell.picked`); нет ходов — новое поле и мана сгорает. Бой сохраняется после каждого хода (`saveBattle`, ключ `aaaa-battle-<ячейка>`) и продолжается после выхода (`loadBattle`). Состояние `battle` (`js/battleState.js`): `startBattle(enemyId)` → `attemptSwap` → `swapAndResolve` → `resolveBoard` (`applyMatchEffects`) → `endTurn` → `enemyTurn` (`chooseEnemyMove`/`scoreMove`) → `finishBattle` → окно `#battleResult`. В начале боя здоровье полное, щит и мана 0.
- Прогрессия как в WoW Classic: `js/xpTable.js` (опыт до уровня 1–60), опыт за врага `mobXp` (45+5×ур., ±уровни, серые — 0, элита ×2), цвет сложности `difficultyOf`, характеристики от уровня `combatStats`. Опыт и изолента с фишек остаются и при поражении, опыт за врага — только за победу (`finishBattle`, `grantXp`). Изолента хранится в белых (`tape`), показывается `formatTape`.
- Карта врагов (экран `map`, `openMap`/`renderMap`/`chooseEnemy`): 9 локаций из документа автора — `js/zones.js` (по три у Совета и Союза, три нейтральные; у локации `factionId`, `start` — расы, которые там начинают, `gems` — фишки, выпадающие чаще (`randomGemType`), описание, 4 врага из списка автора, последний — элита; у врага `skill` — навык, `short` — что он делает (пока только текст: название в карточке карты, описание под панелью врага в бою — `renderEnemySkill`; в бою не работает), `description` — лор). Уровни: у фракций 1–15 / 16–30 / 31–45, общие «Переход» 25–40, «Запасник‑9» 40–55, «Ржавый периметр» 46–60. Все расы фракции начинают в её первой локации: Совет — «Учёт и Ржавчина», Союз — «Ветер и Торговля». Стартовая локация — `startZoneOf` (Пресса — по фракции класса, Хронист — «Учёт и Ржавчина»), доступ — `zoneAllowed` через `mapSide` (своя фракция + нейтральные; Пресса — фракция класса; Хронист — все), чужие — закрыты и чёрно-белые. Стартовая локация пишется при выборе расы.
- Игра «3 в ряд»: настройки в `js/match3Config.js` (поле 9×9, подсказка через 10 с, длительности анимаций), фишки — `js/gemTypes.js` (формы и цвета из макета), состояние — `match3` (`js/match3State.js`). Цикл хода: `attemptSwap` → `resolveBoard` (`findMatches` → `clearGems` → `collapseAndRefill`, пока есть ряды) → без ходов `rebuildBoard`. Управление — `setupBoardInput` (перетаскивание или два касания), подсказка — `scheduleHint`/`showHint`/`clearHint`.
- Сохранения: 3 ячейки персонажей, ключи localStorage `aaaa-slot-1..3`, выбранная — `aaaa-active-slot`; настройки — `aaaa-settings`, новые поля добавлять в `DEFAULT_SETTINGS` (`js/state.js`).
- Глоссарий-книга (экран `glossary`, `openGlossary`/`renderGlossary`, кнопка «Глоссарий» в меню и квадратная кнопка-книга в бою): разделы — `js/glossarySections.js`, каждый строится своей функцией `glossary<Раздел>.js` прямо из файлов данных (фишки, бой, фракции, расы, классы, навыки, локации и враги, опыт и изолента), запись — `glossaryEntry`, подзаголовок — `glossaryHeading`.
