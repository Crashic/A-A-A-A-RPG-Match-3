# A-A-A-A Match 3 RPG — заметки для Claude

Мобильная match-3 RPG в браузере и как PWA. Репозиторий: crashic/A-A-A-A-RPG-Match-3, игра: https://crashic.github.io/A-A-A-A-RPG-Match-3/
С версии 0.1.0 игра делается с нуля (старый код «Осколков Бездны» удалён, он есть в истории git до коммита b3f1c1e).

## Правила работы с пользователем
- Отвечать по-русски, о себе в женском роде («сделала»).
- «ИЗ АРТЕФАКТА» в сообщении пользователя — взять этот элемент из дизайн-системы (ссылка ниже, копия в `design/`).
- Сеттинг: постапокалипсис в фэнтезийной России (Fallout по-русски с киберпанком); герой живёт в бункере и выходит на поверхность за провизией. Валюта — изолента: синяя / чёрная / белая (как золото / серебро / медь, 1:100:100).
- Выбор вариантов и пунктов меню — опросом (AskUserQuestion).
- Устройство: телефон 1080×2460, Android 13+, управление касанием и перетаскиванием. Всё приложение в ГОРИЗОНТАЛЬНОЙ ориентации: CSS ~820×360 (manifest `landscape`, в браузере — `lockLandscape` после входа в полный экран). Если телефон держат вертикально (или выключен автоповорот), всё приложение рисуется повёрнутым на 90° (CSS в конце `style.css`, размеры экрана — `--app-w`/`--app-h`, а не vw/vh); координаты касаний переводить через `toAppPoint`/`appRect`. Проверять и 360×820 (повёрнутый режим).
- Списки (локации, разделы, классы, враги…) — кнопки по высоте содержимого, НЕ растягивать на всю высоту блока.
- Мелкая правка — «в файле X найди это, замени на это»; заметная — файлы целиком с путями; новая подсистема или много файлов — сначала спросить (архив или пуш).
- Перед крупной пересборкой проекта уточнять и объяснять, почему так рациональнее.
- В конце архива указывать версию.
- Перед выпуском СПРАШИВАТЬ пользователя опросом: какой номер версии присвоить и какой текст внести в список изменений (предложить варианты). Самой версию не выбирать и текст не вписывать.
- После правок: проверить Playwright (viewport 820×360 телефон лёжа + ПК 1366×768, без ошибок в консоли; всё должно помещаться по высоте 360 без прокрутки), выставить согласованную `APP_VERSION`, добавить согласованную запись в `js/changelog.js`, закоммитить и запушить в main.
- Список изменений (`js/changelog.js`, открывается нажатием на версию): новая версия сверху, максимально коротко, только главное — «добавили 25 предметов», «создали систему квестов».
- Формат версии у пользователя свободный (например `0.1.a`); для обновления важна только смена строки, порядок номеров не важен.

## Дизайн
- Весь интерфейс и графика — по дизайн-системе пользователя: https://claude.ai/artifact/R918BS9sRLVB4Q6fLH64d4. Пользователь её часто дорабатывает — ПЕРЕД ЛЮБОЙ правкой интерфейса (не только графики) открывать макет, сверять с копией в `design/` и обновлять её, без напоминаний (`README.md` — правила, `tokens.json` — палитра, `icon-guide.md` — как рисовать иконки, `components/*/` — образцы).
- Палитра фэнтези-кита: фон экранов — закатное небо `bg-sky-top → bg-sky-mid → bg-sky-bottom`; камень `bg-canvas` — панели; ячейки поля `bg-cell` / `bg-cell-alt` шахматкой; 7 камней по ступеням светлоты (у каждого `-light` и `-dark`): `gem-amethyst` (треугольник), `gem-sapphire` (капля), `gem-ruby` (квадрат), `gem-emerald` (шестиугольник), `gem-aquamarine` (крест), `gem-topaz` (звезда), `gem-pearl` (круг). Интерфейс: `ui-outline` (обводка), `ui-metal` (рамки), `ui-primary` («да», текст на ней тёмный `ui-outline`), `ui-danger` («нет», светлый текст), `ui-reward` (золото, тёмный текст), `ui-ribbon` (ленты, магазин), `ui-parchment`, `ui-gold-shadow`; текст `text-primary/secondary/muted`.
- Фишки (`GemsElemental`, вариант A): одинаковый сквиркл цвета камня, внутри иконка ресурса тёмным тоном (55 %), поверх «Верхний глянец» (`#gemGlossGrad`; ободок `gemRim` виден только у выбранной фишки); ресурсы: рубин — топливо, аквамарин — детали, изумруд — травы, топаз — радиация, сапфир — металл, аметист — плёнка, жемчуг — документы. Выбор — без увеличения, ободок яркий; подсказка — мигает на 20 % ярче + «Полосы». Поле (`BoardSample`) 9×9, клетка 46 px, фишка 40 px. Те же плитки-иконки для фракций, рас, классов и пола — `iconTile` (силуэты в `js/originIcons.js`).
- Базовые элементы плоские; «стёкла» (`GlassOverlays`) накладываются отдельно, не больше двух на элемент.
- Цвета только через переменные `css/tokens.css`; он генерируется: `python3 tools/build-tokens.py` (после обновления `design/tokens.json`).
- Кнопки `.btn` + цвет: `green` — главное действие (`ui-primary`), `red` — выход/опасность, `orange` — награда, `purple` — магазин, `stone` — второстепенное; `round` — круглая иконка. Ленты `.ribbon` — только в окнах (у экранов заголовков нет), контейнер — `.panel` (камень `bg-canvas` с кромкой `ui-metal`). Поле — клетки шахматкой на подложке `ui-outline` (без рамки вокруг — так просил пользователь).
- Шрифты — три роли из макета (`TypeSystem`): Noto Sans Display — заголовки; Noto Sans — кнопки, меню, основной текст; IBM Plex Sans — мелкий текст и цифры (tabular-nums). В CSS — готовые стили `font: var(--type-title|heading|score|button|menu|body|body-strong|small|stat|caption)` и трекинг `var(--type-<стиль>-ls)` из `css/tokens.css`. Файлы локально в `fonts/` (не Google Fonts — нужен офлайн), подключены в `css/fonts.css`.

## Структура
- Движок: HTML + CSS + JS, классические скрипты с общей глобальной областью.
- Каждая функция — отдельный файл в `js/`, имя файла = имя функции. Порядок подключения в `index.html` важен, `js/main.js` последний.
- Спрайты — в `sprites/`.
- Новый скрипт или стиль подключать в `index.html`, затем `python3 tools/update-sw.py` — он пересобирает список `FILES` в `sw.js` (скрипты, стили, шрифты, спрайты).
- Экраны — `<section class="screen">` в `index.html` (menu, characters, create, intro, settings, game, map, bye), переключение `showScreen(id)`; каждый переход пишется в history, «Назад» телефона возвращает на предыдущий экран через `renderScreen(id)`.
- Персонаж (таблицы автора): иерархия Фракция → Раса → Класс: фракции `js/factions.js` (Совет Управляющих и Союз Вольных — по три расы; Пресса — фракция и раса сразу, 7 классов: 4 адаптированных + 3 уникальных; у класса Прессы `side` — фракция класса (Совет: Инженер, Надзиратель, Архивариус; Союз: Механик, Засадник, Бард; Хронист — нейтральный); на экранах классы Прессы — две колонки по фракциям, Хронист посередине — `fillPressColumns`), расы `js/races.js` (у расы `classes` — доступные классы с бонусом), классы `js/classes.js`, пол `js/genders.js`. Бонус «+1 % к ресурсу» усиливает фишку в бою — `gemBonus`. Создание: экран «Происхождение» (`renderOriginStep`: фракции, расы, Пресса посередине; недоступное — чёрно-белое; выбранная кнопка — без обводки, фон «Небо низ», текст «Обводка») → «Класс» (`renderClassStep`: классы фракции `factionClassList`, имя, пол, «Создать персонажа»; недоступный расе класс — «Таких выживших не существует»), «Случайно» — `randomCharacter`. На сенсорных экранах имя вводится своей клавиатурой (`#keyboard`, `renderKeyboard`) — системная не поворачивается вместе с игрой. В ячейке хранится `{ name, serverId, modeId, classId, genderId, raceId, factionId, level, xp, tape, lastEnemy, created, updated, version }`.
- Навыки (документ автора, адаптированы к бою): `js/skills.js` — по 2 навыка на «раса:класс» (адаптированные классы Прессы берут навыки расы-источника — `PRESS_SKILL_SOURCE`), у навыка `lore` (оттенок расы) и `text` (что делает в бою). Пассивные (`effects` с `on`: gather, gemPct, stack, allPct, start, firstHit, dmgReduce, lowHp, shieldBroken, single, afterActive, notes) — `hasPassive`, `skillGemPct`, `skillAfterGather`, `skillReduceHit`, `skillAfterHeroHit`, `skillTurnEnd`, `skillBattleStart`. Активные — кнопки за ману под панелью героя (`renderSkillBar`, `canUseSkill`, `useSkill`; act: show, ward, shield, heal, buff, undo — ход не тратят; calibrate, convert — меняют поле и тратят ход). Состояние — `battle.skill` (`createSkillState`, сохраняется с боем). Навыки показываются на экране выбора класса. Боевые навыки классов — `js/classSkills.js` (`CLASS_SKILLS`, по одному на класс, у всех рас одинаковый, первым в `heroSkills`): активный за одну ману, ход не тратит, перезарядка `cooldown` ходов игрока (`battle.skill.cooldowns`, уменьшается в `skillTurnEnd`), act `strike` — `skillStrike` (mult × атака, pierce, breakShield, drain, ward, selfShieldPct, lifesteal); на кнопке — значок маны, цена и перезарядка.
- Стиль игровых текстов (навыки, враги, лор): юмор с сарказмом, постапокалиптический СССР, ориентиры — WoW, Fallout, Аллоды Онлайн.
- Характеристики (как в WoW Classic): `js/statsConfig.js` (`STATS` — Сила/Ловкость/Выносливость/Интеллект/Дух, коэффициенты), база классов `js/classStats.js`, названия по расам `js/statNames.js` (стили council/union/under/press — тексты автора, `statName`, подсказка `statTipText`). Значение = база класса + `hero.points` (розданные очки); свободных — `statPointsFree`. В бою — `createHeroFighter` (атака, здоровье, крит `rollCrit`, запас/приток маны `manaMax`/`manaPct`, щит за Детали и лечение навыков `healPct`). Свободных очков — 5 за уровень начиная со 2-го (`statPointsTotal`). Экран «Персонаж» (`character`, `renderCharacter`): слева шапка `renderCharHead` (имя по центру, уровень и опыт), кукла `renderDoll` (пары слотов слева–справа по порядку автора: Голова–Плечи, Амулет–Грудь, Пояс–Руки, Кольцо–Ноги, Кольцо–Обувь, Оружие–Оружие — `DOLL_SLOTS` в `js/inventoryConfig.js`; в слотах значки `slotIcon`, название — подсказкой; оружие вдвое выше; под куклой 5 рун), характеристики `renderStatBlock` (вкладки «Характеристики» / «Подробно» — `statTab`, `renderStatDetails`: здоровье, атака, крит, мана, щит, лечение; «−/+» `changeStat`, сброс `resetStats` — оранжевый, если есть розданные очки, с подтверждением; только вне боя, в бою кнопок нет), вкладки класса, фракции и расы `renderCharTabs` (`charTab`); справа инвентарь `renderInventory` (ряд гнёзд сумок `bagNestRow`, ячейки по `bagCapacity`, внизу изолента); «Свободно очков: свободные / всего». Пустые слоты — `emptySlot`. Значки характеристик — `statChip`/`renderStatChips` (меню, создание персонажа). Раздел «Характеристики» в глоссарии.
- Предметы (как Diablo 2 / PoE): редкости `ITEM_RARITIES` (обычный, магический, редкий, уникальный; цвета — токены), выпадение и уровни — `js/itemConfig.js`; базы `js/itemBases.js` (слот, род для прилагательных, главная характеристика, шутка); случайные свойства `js/itemAffixes.js` (приставка в 4 родах + окончание «… грузчика»; str/agi/sta/int/spi, hp, crit, tape, xp); уникальные `js/itemUniques.js` (свойства в долях `itemAffixRange`). Генерация `rollItem(level, rarity)`, добыча `rollDrops` в `finishBattle` (только победа) → `addToBag`. Шанс вещи `ITEM_DROP_CHANCE` = 0.2, элита — 1 вещь. Редкости: веса 66 / 28 / 5 / 0,6 %, сила свойств `power` ×1 / ×1 / ×2 / ×4 (с редкого каждая следующая ×2, `rollItem`). Хлам (`JUNK_ITEMS`, `makeJunk`, `isJunkItem`, редкость `junk` — цвет `ui-metal`, только продать/выбросить — `openJunkInfo`, «Сдать хлам» продаёт хлам и обычные). Ресурсы (`RESOURCES`, `rollResources` → `addResources` в `acc.resources`, общие для аккаунта; значок `resourceIcon`; показаны строкой в лагере — `campResourceRow`). Окно итогов: добыча иконками (`renderResultLoot`, касание — окно вещи с «Продать»/«Надеть» и сравнением; проданное исчезает), ресурсы — значками. В сохранении: `hero.bag` (массив, не больше `bagCapacity(hero)`) и `hero.gear` (ключи `GEAR_KEYS`: ring1/ring2, weapon1/weapon2, rune1–5). Свойства снаряжения — `gearTotals` → `heroStats` (характеристики) и `createHeroFighter` (здоровье, крит, изолента, опыт). Ячейка вещи `itemSlot` (на ПК при наведении — подсказка `itemTipText`, название цветом редкости), окно `openItemInfo` (сравнение с надетым: разница и блок «Сейчас надето» с его свойствами; в подсказке при наведении — «Надето: …», `itemWornTip`; цена `itemPrice`), `equipItem`/`unequipItem`/`dropItem` → `saveGear`; в бою менять нельзя (`statsLocked`). Раздел «Предметы» в глоссарии, «Выдать предмет» в «Читере».
- Оружие: одноручное (в окне — «В левую» `weapon1` / «В правую» `weapon2`, `equipItem(index, key)`) и двуручное (база `hands: 2`, `isTwoHanded`; кувалда, двустволка, арбалет, подшивка, хоругвь): всегда в `weapon1`, видно в обеих руках (во второй — бледная копия `.twoHandEcho`), надевание снимает оба оружия, одноручное вместо двуручного снимает его. Свойства двуручного ×`TWO_HAND_MULT` = 3 (`itemMods`), но бьёт через ход: в бою после хода с уроном Топливом `battle.skill.swingCd` = 1 — следующий ваш ход Топливо урона не даёт («Замах…», лог), иконка «Замах» среди иконок героя (`heroTwoHanded`, `skillTurnEnd`, `heroBuffIcons`). Текст вида — `weaponKindText` (окно и подсказка).
- Бункер и торговец (`js/shopConfig.js`): вход — люк «Бункер» в столбце меню (`openBunker`/`renderBunker`: карточки «Завхоз Семёныч» → `openShop`/`renderShop` и «Доска объявлений» → `openQuests`); отдельных иконок торговца и доски в меню НЕТ (пользователь убрал). Прилавок `hero.shop = { items, level, wins }` — `shopStock` завозит новый при новом уровне или через `SHOP_REFRESH_WINS` побед (`hero.wins` растёт в `finishBattle`), `rerollShop` — за изоленту (`rerollPrice`). Покупка `buyItem` (`buyPrice` = `itemPrice` × 4), продажа `sellItem`, «Сдать хлам» `sellJunk` (все обычные). Окно предмета: `{ shop: i }` — «Купить», `{ bag: i, sell: true }` — «Продать»/«Надеть». Значки `SHOP_ICON`, `BUNKER_ICON`, `BOARD_ICON`. Изолента текстом — `tapeText`. Раздел «Бункер» в глоссарии.
- Сумки (`js/bagConfig.js`, как в WoW/GW2): ячейки инвентаря дают ТОЛЬКО надетые сумки (`bagCapacity`; констант BACKPACK_SLOTS/BAG_SLOTS больше нет). `hero.packs = { nests, worn }` (`heroPacks`; старым персонажам `loadSlot` сразу выдаёт авоську 8 и, если вещей больше, «Чемодан из прошлой жизни» под остаток). Сумка — вещь с `bagType`, `size` (`makeBag`, `isBagItem`), в инвентаре занимает ячейку; окно — `openBagInfo` (из `openItemInfo`), надеть `wearBag` (в первое свободное гнездо), снять `takeOffBag` (последнюю нельзя; если вещи не влезут — предупреждение «вы делаете глупость… разворуют», при согласии теряются последние вещи). Гнёзда: старт `BAG_NESTS_START` = 2, до `BAG_NESTS_MAX` = 5, «+» — `buyBagNest` (`BAG_NEST_PRICES`). Сумки продаёт Семёныч (раздел «Сумки» на прилавке, `buyBag`), «Сдать хлам» сумки не продаёт. Подсказка с мотком изоленты — атрибут `data-tip-tape` (сумма, `showTip` дорисует `formatTape`). Раздел «Сумки» в глоссарии «Бункер».
- Банк (`js/bankConfig.js`, как в WoW; в игре называется «Шкафчик» — `BANK_NAME`, вахтёрша Нина Петровна; ячейки сразу под гнёздами): у КАЖДОГО персонажа свой, `hero.bank = { items, bags }`; `BANK_BASE_SLOTS` = 28 + до `BANK_BAG_SLOTS` = 7 гнёзд по +`BANK_BAG_SIZE` = 12, гнёзда покупаются по очереди (`buyBankBag`, цены `BANK_BAG_PRICES` 10 белой … 25 синей), размер — `bankSize`. Экран `bank` (`openBank`/`renderBank`, кассир Нина Петровна): касание по вещи перекладывает сумка ↔ банк (`bankMove`). Вход — карточка «Банк» в Бункере (в столбце меню места нет — 8 пунктов уже максимум). В глоссарии — в разделе «Бункер».
- Задания (`js/questConfig.js`): категории `QUEST_CATEGORIES` (у задания поле `cat`): сюжетные `story` (по ходу игры, пока нет), побочные `side` (до 20, у персонажей — появятся позже, не с доски), поручения `errand` (с доски, до 3), ежедневные `daily` (с доски, взять 3 / с 10 ур. 4 / с 20 ур. 5 — `questLimit`, `QUEST_DAILY_LIMITS`; новые каждый день в 6:00 — `questDayKey`, невыполненные взятые сгорают). `hero.quests = { board, daily, day, active, done }` (`questBoard` дополняет поручения до `QUEST_BOARD_SIZE`, ежедневных — `QUEST_DAILY_BOARD_SIZE` в новый день; старые задания без `cat` → поручения), `rollQuest(hero, cat)`, `acceptQuest(index, 'board'|'daily')`; экран — вкладки доски `questBoardTab` и своих заданий `questTab`, виды `QUEST_TYPES` (zone, enemy, elite, gems, wins; шаблоны текста с {zone}/{enemy}/{n}/{times}/{gem}, авторы — `QUEST_GIVERS`), генерация `rollQuest` (цели — `questEnemies`: доступные, не серые), награда: опыт (`mobXp` × xp × need), изолента, вещь (за элиту — редкая). Прогресс — `questProgress` в `finishBattle` (фишки героя копятся в `battle.gained.gems` в `applyMatchEffects`, считаются и при поражении). Экран `quests`: `renderQuests`/`questCard`, `acceptQuest`, `abandonQuest`, `turnInQuest` → `saveQuests`. Множественное число — `plural`, название фишки — `gemName`.
